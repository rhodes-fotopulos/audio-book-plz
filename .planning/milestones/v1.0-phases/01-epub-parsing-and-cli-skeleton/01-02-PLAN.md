  <behavior>
**Dialogue Detection (PARSE-04):**
- `"Hello," she said.` → dialogue (straight double quotes)
- `\u201cHello,\u201d she said.` → dialogue (curly double quotes)
- `\u2018Hello,\u2019 she said.` → dialogue (curly single quotes)
- `He said it was "fine" but looked worried.` → dialogue (quoted speech within narration — conservative: if quotes present, tag as dialogue for Phase 2 to refine)
- `The cat's meow echoed.` → narration (apostrophe, not dialogue quote)
- Multi-paragraph speech: paragraph opens with `\u201c` but has no closing `\u201d` → dialogue, carry state to next paragraph. Next paragraph without opening quote but has closing `\u201d` → also dialogue. Reset state at chapter end.

**Type Classification (PARSE-03):**
- `('h1', 'Chapter 1', {})` → chapter_heading
- `('h2', 'The Dark Tower', {})` → chapter_heading
- `('hr', '', {})` → scene_break
- `('p', '* * *', {})` → scene_break
- `('p', '---', {})` → scene_break
- `('p', '', {'class': ['separator']})` → scene_break
- `('p', '"Where are you going?" she asked.', {})` → dialogue
- `('p', 'The sun set behind the mountains.', {})` → narration
- `('blockquote', 'Dear John, I am leaving...', {})` → dialogue (letters/notes per user decision: tag as dialogue for Phase 2 attribution)

**Segment Splitting (PARSE-06):**
- 200-char sentence → 1 segment (under limit)
- 350-char sentence → 2 segments (split at clause boundary: comma, semicolon, em-dash)
- 500-char sentence with no clause boundaries → 2 segments (force split near midpoint at word boundary)
- 3 sentences totaling 400 chars → 3 separate segments (one per sentence, each under limit)
- Dialogue line of 100 chars → 1 segment (kept together per user decision: "Dialogue lines from one speaker are kept as a single segment when they fit within the limit")

**NLTK punkt startup:**
- Auto-download `punkt_tab` if not present (quiet=True to avoid cluttering CLI output)
  </behavior>
  <implementation>
Create `src/parser/segmenter.py` with:

1. **Module-level NLTK bootstrap**: `ensure_nltk_data()` called at import time — downloads `punkt_tab` if missing (per research Pattern: NLTK Sentence Tokenizer with Startup Download, and Pitfall 3).

2. **`CHAR_LIMIT = 280`** — module constant (per research discretion recommendation: 280 chars is the safe ceiling with 20-char buffer below Chatterbox's ~300 hard limit).

3. **Dialogue detection regex**: Cover `"..."` (straight), `\u201c...\u201d` (curly double), `\u2018...\u2019` (curly single). Use a pattern that checks if the paragraph STARTS with an opening quote or contains quoted speech. Do NOT match apostrophes in contractions as dialogue — the straight single quote `'` should NOT be treated as a dialogue opener unless it's a curly `\u2018` (per research Pattern 3). Avoid matching `it's`, `don't`, `can't` as dialogue.

4. **`classify_block(tag_name: str, text: str, attrs: dict, dialogue_open: bool) -> tuple[str, bool]`**: Returns `(segment_type, new_dialogue_open_state)`.
   - `tag_name in ('h1', 'h2', 'h3', 'h4')` → `chapter_heading`, reset dialogue state
   - `tag_name == 'hr'` → `scene_break`, reset dialogue state
   - Text matches scene break pattern (`* * *`, `***`, `---`, `\u2014\u2014\u2014`, solo `#`, etc.) → `scene_break`
   - CSS class contains "break", "separator", "divider" → `scene_break`
   - `tag_name == 'blockquote'` → `dialogue` (letters/notes per user decision)
   - Text starts with or primarily contains quoted content → `dialogue`
   - `dialogue_open` is True (multi-paragraph speech continuation) and text does not start with a quote → `dialogue` (carry state)
   - If text has opening quote without closing quote → set `dialogue_open = True`
   - If text has closing quote matching open state → set `dialogue_open = False`
   - Otherwise → `narration`

5. **`split_to_segments(text: str, segment_type: str) -> list[str]`**: Splits text into chunks <= CHAR_LIMIT.
   - Use `nltk.tokenize.sent_tokenize(text)` for sentence boundaries.
   - Each sentence that fits becomes its own segment (per user decision: "Split text at sentence boundaries — each sentence becomes its own segment").
   - Sentences exceeding CHAR_LIMIT → force-split at nearest clause boundary (comma `,`, semicolon `;`, em-dash `\u2014` or `--`) per user decision.
   - If no clause boundary found → force split at nearest word boundary near midpoint.

6. **`process_chapter_blocks(blocks: list[tuple[str, str, dict]], chapter_num: int, chapter_title: str, start_id: int) -> list[Segment]`**: Orchestrator function.
   - Iterates blocks, classifies each, splits text, creates `Segment` instances with sequential IDs starting from `start_id`.
   - Tracks `dialogue_open` state across blocks within the chapter; resets at chapter end.
   - Returns list of Segment objects.
  </implementation>
