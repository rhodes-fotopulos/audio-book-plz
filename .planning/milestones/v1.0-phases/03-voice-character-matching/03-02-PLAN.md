Create trait_matcher.py with two functions:

**match_character_llm(character: CharacterProfile, candidates: list[SpeakerAnnotation], assigned_ids: set[str] = set()) -> VoiceAssignment | None:**
- Build a system prompt instructing Qwen3 8B to act as a casting director matching a character to a voice actor
- System prompt must emphasize: balanced blend of gender/age/vocal quality (per user decision), distinctiveness matters, include brief reasoning for each match
- User content includes: character name, gender, age_range, voice_qualities (pitch, pace, tone, accent), personality traits, description, AND a list of candidate speakers with their annotation traits
- Exclude already-assigned speaker_ids from candidates (pass via assigned_ids)
- Use call_llm_structured() from src/attribution/llm_client.py with a new Pydantic response schema:
  - **MatchResponse(BaseModel):** speaker_id: str, reasoning: str, confidence: float
- If LLM returns a speaker_id not in candidates, retry up to 2 times
- If all retries fail, return None (caller falls back to embedding matcher)
- Set method="llm" on returned VoiceAssignment

**match_narrator_llm(characters: list[CharacterProfile], segments: list[dict], candidates: list[SpeakerAnnotation], narrator_mode: str, assigned_ids: set[str] = set()) -> VoiceAssignment:**
- For first_person narrator_mode: find the protagonist (most dialogue lines), use their voice traits to match narrator. The reasoning should note "first-person narrator = protagonist voice"
- For third_person narrator_mode: analyze the first few narration segments to infer book tone (dark/light/neutral). Build a narrator trait description based on tone. System prompt should say "Match a narrator voice that fits the book's tone — dark thrillers get lower/tense voices, comedies get lighter voices" (per user decision)
- Use same call_llm_structured pattern
- Set character_name="narrator" on returned VoiceAssignment

**Pydantic schema for LLM response:**
```python
class MatchResponse(BaseModel):
    model_config = ConfigDict(strict=True)
    speaker_id: str
    reasoning: str
    confidence: float
```

- Test that assigned_ids are excluded from candidate list in the prompt
- Test match_narrator_llm in first_person mode — verify protagonist detection
- Test match_narrator_llm in third_person mode — verify tone analysis prompt
- Mock tests only (no actual LLM calls) — use unittest.mock.patch on call_llm_structured

Create embedding_matcher.py with two functions:

**build_speaker_embeddings(speakers: list[SpeakerAnnotation]) -> tuple[list[str], any]:**
- Load all-MiniLM-L6-v2 on CPU: `SentenceTransformer("all-MiniLM-L6-v2", device="cpu")`
- Encode each speaker's trait_text into 384-dim embeddings
- Return (speaker_ids_list, embeddings_tensor)
- Cache the model instance at module level (load once per session)
- Log: "Built embeddings for {N} speakers"

**match_character_embedding(character: CharacterProfile, speaker_ids: list[str], speaker_embeddings: any, assigned_ids: set[str] = set(), top_k: int = 5) -> VoiceAssignment:**
- Build a natural language description from character traits: combine gender, age_range, voice_qualities (pitch, pace, tone, accent), personality traits into a single descriptive sentence
- Encode the character description with the same model
- Compute cosine similarity against all speaker embeddings using util.cos_sim
- Exclude already-assigned speaker_ids
- Return the top match as VoiceAssignment with:
  - method="embedding"
  - confidence = cosine similarity score (0-1)
  - reasoning = f"Embedding match (similarity: {score:.3f}) — {character_desc} best matches speaker {speaker_id} traits"
  - warning = set warning if confidence < 0.5 ("Weak embedding match — consider manual review")

**Tests (tests/test_embedding_matcher.py):**
- Test build_speaker_embeddings returns correct shape (N speakers, 384 dims)
- Test match_character_embedding returns a valid VoiceAssignment
- Test that assigned_ids are excluded from results
- Test warning flag is set for low-confidence matches
- Test with a small set of mock speakers (3-5) with known trait distributions
- These tests DO load the real sentence-transformers model (integration test) — mark with @pytest.mark.slow if needed. The model is 80MB and runs on CPU, so it's fast enough for CI.

**TDD approach — write tests first, then implement.**

Create dedup.py with one main function:

**enforce_uniqueness(assignments: list[VoiceAssignment], classification: CastClassification, segments: list[dict], candidates_by_character: dict[str, list[SpeakerAnnotation]], speaker_ids: list[str] | None = None, speaker_embeddings: any | None = None) -> list[VoiceAssignment]:**
- Check for duplicate speaker_ids among major character assignments
- For each duplicate pair among major characters:
  - Keep the assignment with higher confidence
  - Re-match the lower-confidence character to the next-best speaker:
    1. Try embedding matcher if speaker_embeddings provided
    2. Otherwise pick next available speaker from that character's candidate pool
  - Per user decision: "swap a less-perfect individual match for more contrast when two characters sound too similar"
  - Update reasoning to note the swap: "Reassigned for distinctiveness — originally matched speaker {X}"
- Check minor characters: two minor characters who appear in the same chapter must NOT share a speaker
  - Build chapter co-occurrence: for each pair of minor characters, check if any segment in the same chapter has both as speakers
  - If co-occurring minors share a speaker, reassign the one with lower confidence
- Return updated assignments list
- Log any swaps made: "Dedup: swapped {character} from speaker {old} to {new} for uniqueness"

**Helper: _get_chapter_cooccurrence(segments: list[dict]) -> dict[tuple[str, str], bool]:**
- For each chapter, collect all unique speakers
- For each pair of speakers in the same chapter, record co-occurrence
- Return dict of (speaker_a, speaker_b) -> True

**Tests (tests/test_dedup.py):**
- Test no changes when all major characters have unique speakers
- Test swap when two major characters share a speaker — verify higher confidence kept
- Test minor characters sharing is allowed if different chapters
- Test minor characters sharing is NOT allowed if same chapter — verify reassignment
- Test that warning flag is set on reassigned characters if match quality drops
- Test edge case: only one candidate available (no swap possible) — assignment kept with warning
