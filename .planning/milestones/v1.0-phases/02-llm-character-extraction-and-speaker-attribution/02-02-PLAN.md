    **Constants:**
    - `SYSTEM_PROMPT_TOKENS = 500` — budget for system message
    - `RESPONSE_BUDGET = 4096` — max tokens for LLM response
    - `AVAILABLE_FOR_CONTENT = CONTEXT_WINDOW - SYSTEM_PROMPT_TOKENS - RESPONSE_BUDGET` — ~28,172 tokens for chapter text
    - `MAX_CONTENT_CHARS = AVAILABLE_FOR_CONTENT * 4` — character limit (~112,688 chars)

    **System prompt for extraction** (stored as module-level constant `EXTRACTION_SYSTEM_PROMPT`):
    ```
    You are a character extraction specialist for audiobook production. Extract ALL characters from the provided chapter text.

    For each character found:
    - name: The character's most commonly used name in this chapter
    - aliases: Any other names, titles, or references used for this character
    - gender: male, female, non-binary, or unknown
    - age_range: child, young adult, middle-aged, elderly, or unknown
    - voice_qualities: Infer pitch, pace, tone, and accent from text descriptions and dialogue style
    - personality_traits: Key personality characteristics shown in this chapter
    - relationships: Known relationships to other characters
    - description: One-sentence character summary
    - is_named: true if character has a proper name, false if referred to by description only (e.g. "the bartender")

    Rules:
    - Extract EVERY character who speaks or is mentioned by name, no matter how minor
    - For unnamed speakers (e.g. "the old man", "a soldier"), create profiles with is_named=false
    - Infer voice qualities from context: "the old man grumbled" implies elderly male, low pitch, slow pace, gruff tone
    - Include character relationships when evident from text
    - When unsure about a trait, use "unknown" — do not guess without textual evidence
    ```

    **`extract_characters_from_chapter(chapter_text: str, chapter_num: int, cache_dir: Path) -> list[CharacterProfile]`:**
    - Compute cache key via `get_cache_key(chapter_text, "extraction")`
    - Check cache — if hit, return cached profiles (deserialize back to CharacterProfile list)
    - If chapter text exceeds MAX_CONTENT_CHARS, split into sub-chunks at scene break boundaries (look for segments with type "scene_break") or at paragraph boundaries. Process each sub-chunk separately and combine results.
    - Call `call_llm_structured(EXTRACTION_SYSTEM_PROMPT, chapter_text, ChapterExtractionResult)`
    - If LLM returns None (all retries failed): log warning, return empty list
    - Write result to cache
    - Return list of CharacterProfile

    **`extract_all_characters(segments: list[dict], cache_dir: Path, progress_callback: Callable | None = None) -> dict[int, list[CharacterProfile]]`:**
    - Group segments by chapter number
    - For each chapter: concatenate segment text (joining with newlines), call extract_characters_from_chapter
    - If progress_callback provided, call it after each chapter with (chapter_num, total_chapters)
    - Return dict mapping chapter_num -> list of CharacterProfile extracted from that chapter
    - Uses `estimate_tokens` from llm_client to check chapter size before sending

    **`_build_chapter_text(segments: list[dict]) -> str`:**
    - Helper that concatenates segment text for a chapter
    - Preserves segment type context by prefixing dialogue lines with their type in brackets for the LLM:
      - `[DIALOGUE] "Hello," she said.`
      - `[NARRATION] The sun set behind the hills.`
      - `[CHAPTER_HEADING] Chapter 5: The Storm`
    - This helps the LLM distinguish dialogue from narration for better extraction

    **`_split_chapter_text(chapter_text: str, max_chars: int) -> list[str]`:**
    - Splits oversized chapter text into chunks that fit in the context window
    - Prefers splitting at scene breaks (lines starting with `[SCENE_BREAK]`)
    - Falls back to splitting at paragraph boundaries (double newlines)
    - Each chunk should be at least 1000 chars to avoid trivially small requests

    Create `src/attribution/merger.py` that merges per-chapter character lists into a single deduplicated registry.

    **`merge_characters(chapter_characters: dict[int, list[CharacterProfile]], cache_dir: Path | None = None) -> list[CharacterProfile]`:**
    - Collect all CharacterProfile objects across all chapters into a flat list
    - Run the three-stage merge:
      1. **Exact name match:** Group profiles where `name.lower().strip()` is identical. Merge into one profile, accumulating aliases, traits, and relationships.
      2. **Alias/substring match:** For remaining profiles, check if any profile's name appears as a substring of another profile's name (e.g., "Darcy" in "Mr. Darcy", "Elizabeth" in "Elizabeth Bennet"). Also check if any profile's name appears in another profile's aliases list. Merge matches.
      3. **LLM confirmation (optional, for ambiguous cases):** For profiles that share a surname but differ in first name (e.g., "Mr. Bennet" vs "Mrs. Bennet"), do NOT merge — these are likely different characters. For profiles where substring matching is ambiguous (e.g., "Will" could be "William" or a different character), optionally use LLM to confirm with context. If cache_dir is provided, cache LLM merge decisions.
    - For unnamed characters (is_named=False): Aggressively merge references that likely refer to the same person based on description similarity (e.g., "the old man" in Ch.1 who later becomes "Mr. Wilson" — merge if they share chapter proximity and compatible traits).
    - Return sorted list of CharacterProfile (sorted by: named first, then alphabetically by name)

    **`_merge_two_profiles(primary: CharacterProfile, secondary: CharacterProfile) -> CharacterProfile`:**
    - Takes two profiles that have been determined to be the same character
    - Uses the longer/more formal name as the canonical name (e.g., "Mr. Darcy" over "Darcy")
    - Combines aliases (union of both alias lists + the secondary's name)
    - Merges voice_qualities: prefer non-"unknown" values; if both have values, prefer the one with more textual evidence (heuristic: prefer longer description)
    - Union of personality_traits (deduplicated)
    - Union of relationships (deduplicated by character+relation)
    - Prefers is_named=True if either profile has it
    - Takes the longer description

    **`_names_match_substring(name_a: str, name_b: str) -> bool`:**
    - Returns True if one name is a substring of the other (case-insensitive)
    - Requires the shorter name to be at least 3 characters (avoid matching "I" or "Mr")
    - Examples: "Darcy" / "Mr. Darcy" -> True, "Elizabeth" / "Elizabeth Bennet" -> True, "Mr" / "Mr. Darcy" -> False (too short)

    **`_names_share_surname_only(name_a: str, name_b: str) -> bool`:**
    - Returns True if names share a surname but have different given names/titles
    - Used to PREVENT merging: "Mr. Bennet" and "Mrs. Bennet" share surname but are different characters
    - Splits on spaces, compares last token

    **`_alias_overlap(profile_a: CharacterProfile, profile_b: CharacterProfile) -> bool`:**
    - Returns True if any alias of A matches name or alias of B (case-insensitive), or vice versa
  </action>
