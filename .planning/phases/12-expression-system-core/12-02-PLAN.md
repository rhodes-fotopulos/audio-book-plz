  <behavior>
    - Cache hit: match_character_llm with same character profile + same available candidates returns cached result without LLM call
    - Cache miss: match_character_llm with different character profile makes LLM call and writes to cache
    - Cache invalidation: match_character_llm with same character but different assigned_ids (different available candidates) makes new LLM call
    - Cache miss on narrator: match_narrator_llm with same inputs returns cached result on second call
    - No cache when cache_dir is None: Functions work without caching when cache_dir not provided (backward compatible)
  </behavior>
  <action>
1. In `src/matching/trait_matcher.py`:
   - Add imports: `from pathlib import Path` and `from src.attribution.cache import check_cache, write_cache, get_cache_key`
   - Add `cache_dir: Path | None = None` parameter to `match_character_llm()`.
   - Before the LLM call, compute cache key from character profile + available candidate IDs:
     ```python
     if cache_dir is not None:
         profile_str = character.model_dump_json()
         available_ids = sorted(
             c.speaker_id for c in candidates
             if c.speaker_id not in (assigned_ids or set())
         )
         cache_content = f"{profile_str}|{','.join(available_ids)}"
         key = get_cache_key(cache_content, "trait_match")
         cached = check_cache(cache_dir, key)
         if cached is not None:
             logger.info("Cache hit for character %s", character.name)
             return VoiceAssignment(**cached)
     ```
   - After successful LLM result, write to cache:
     ```python
     if cache_dir is not None and result is not None:
         write_cache(cache_dir, key, result.model_dump())
     ```
   - IMPORTANT: The cache key MUST include the sorted available candidate IDs (candidates minus assigned_ids), not just the character profile. This prevents stale results when the candidate pool shrinks as characters get assigned.

   - Add `cache_dir: Path | None = None` parameter to `match_narrator_llm()`.
   - Similar cache wrapping: key from narrator_mode + protagonist traits (for first_person) or book tone segments (for third_person) + available candidate IDs.

2. In `src/matching/orchestrator.py`:
   - The orchestrator calls `match_character_llm(char, candidates, assigned_ids)` at line 191 and `match_narrator_llm(...)` at line 107.
   - Determine where cache_dir comes from: the orchestrator's `run_matching(book_dir, ...)` has `book_dir`. Use `cache_dir = book_dir / ".cache"`.
   - Pass `cache_dir=cache_dir` to both `match_character_llm` and `match_narrator_llm`.

     - Test cache miss on different character: call with different character profile, assert LLM called again
