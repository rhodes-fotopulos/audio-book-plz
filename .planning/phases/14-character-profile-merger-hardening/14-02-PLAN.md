<objective>
Restructure the merge pipeline to use heuristics for candidate generation and LLM as arbiter for accept/reject decisions. Add cross-name exclusion, trait cap, co-occurrence as LLM signal, post-merge validation, and full audit trail written to merge_audit.json.

Purpose: Eliminate false-positive merges (the core Phase 14 goal) by letting the LLM make ambiguous merge decisions with full context, while keeping exact-match heuristics for obvious cases. Every decision is auditable via merge_audit.json.
Output: Restructured merger.py with 4-stage pipeline (exact match, candidate generation, LLM arbiter, validation), pipeline.py writing merge_audit.json.
</objective>

Restructure src/attribution/merger.py following the architecture from 14-RESEARCH.md. The new pipeline has 4 stages:

**Stage 1 -- Exact name match (keep, add audit):**
- Keep `_merge_by_exact_name` logic but add MergeDecision recording for each merge (action="merged", confidence=1.0, stage="exact")
- Pass `audit` and `all_canonical_names` through

**Stage 2 -- Candidate pair generation (NEW, replaces auto-merge stages):**
- Create `_generate_candidate_pairs(profiles, all_canonical_names)` that:
  - Runs fuzzy match, substring match, alias overlap, title/name match on all pairs
  - Does NOT auto-merge -- collects candidate pairs with merge_reason strings
  - Applies surname-only exclusion (MERGE-07) to filter candidates
  - Records rejected candidates in audit (action="rejected", stage="candidate_generation")
  - Returns list of (profile_a_idx, profile_b_idx, merge_reason, similarity_score) tuples

**Stage 3 -- LLM merge arbiter (NEW, replaces old _consolidate_with_llm):**
- Create `_arbitrate_with_llm(profiles, candidate_pairs, chapter_characters, cache_dir, audit)`
- Build MERGE_ARBITER_PROMPT (from research) that defaults to DIFFERENT
- For each candidate pair, provide: both profile summaries, merge_reason from stage 2, co-occurrence chapters (as signal, NOT gate per MERGE-05)
- Batch all pairs in one LLM call for efficiency on local hardware
- Create a new Pydantic response model `MergeArbiterResult` with list of `MergeArbiterDecision(pair_index, decision: "merge"|"reject", confidence: float, reasoning: str)`
- Apply confidence threshold: >= 0.7 merge, < 0.7 skip (log as rejected)
- Record every LLM decision in audit (stage="llm_arbiter")
- Apply accepted merges using group-based merging (union-find to handle transitive pairs)
- If no candidate pairs exist, skip LLM call entirely
- If cache_dir is None, skip LLM call (same as current behavior)
- Use cache namespace "merge_arbiter_v1"

**Cross-name exclusion (MERGE-04):**
- Modify `_merge_two_profiles` to accept `all_canonical_names: set[str]` parameter
- Before adding any alias, check if it matches a canonical name in the set (case-insensitive)
- Block matching aliases with logged warning
- Thread `all_canonical_names` through all merge calls

**Trait cap (MERGE-06):**
- In `_merge_two_profiles`, after unioning traits, cap at 30
- Primary profile's traits come first (they're listed first in the concatenation)
- Log warning with overflow count

**Post-merge validation (MERGE-02):**
- Create `_validate_merged_profiles(profiles, audit)` function
- Check each profile for: >5 aliases, >50 traits, alias matching another canonical name
- Append warnings to audit.warnings and log to console
- Warn-and-continue (never block pipeline)

**Signature change:**
- `merge_characters` returns `tuple[list[CharacterProfile], MergeAudit]`
- Accepts optional `book_title: str = ""` for audit metadata
- Creates MergeAudit at start, passes through all stages, returns it
- The old 4-stage pipeline becomes: exact merge -> candidate generation -> LLM arbiter -> validation

**Keep existing helper functions** that are still useful: `_names_match_fuzzy`, `_title_name_match`, `_names_match_substring`, `_names_share_surname_only`, `_alias_overlap`, `_merge_voice_profiles`, `_build_cooccurrence`, `_named_pair_cooccurs` (but this last one is only used as a signal input to the LLM prompt, not as a gate).

**Remove/replace:** `_merge_by_fuzzy` (replaced by candidate generation), `_merge_by_substring_and_alias` (replaced by candidate generation), `_consolidate_with_llm` (replaced by LLM arbiter).
