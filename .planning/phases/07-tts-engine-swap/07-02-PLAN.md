  <name>Task 1: Create sentence-boundary text chunker</name>
  <files>src/synthesis/chunker.py</files>
  <action>
Create `src/synthesis/chunker.py` with two chunking strategies:

1. `chunk_text_qwen(text: str, max_chars: int = 580, min_chars: int = 200) -> list[str]`:
   - Target: 500-600 chars per chunk (580 default target to leave room for variance).
   - Uses NLTK `sent_tokenize` (already in codebase, established pattern from Phase 1).
   - Algorithm:
     a. Split text into sentences via `sent_tokenize(text)`.
     b. Accumulate sentences into current chunk.
     c. When adding next sentence would exceed `max_chars`, finalize current chunk and start new one.
     d. NEVER break mid-sentence — if a single sentence exceeds `max_chars`, keep it as its own chunk (don't split words). Log a warning for sentences > 800 chars.
     e. If final chunk is very short (< `min_chars`) AND there's a previous chunk, merge it back into the previous chunk (even if that makes prev chunk slightly over target). This prevents tiny trailing chunks that sound unnatural.
   - Return list of chunk strings, each stripped of leading/trailing whitespace.

2. `chunk_text_chatterbox(text: str, max_chars: int = 280) -> list[str]`:
   - This is the OLD chunking logic preserved for Chatterbox fallback (per user decision: keep both chunking strategies available).
   - Reuse the exact algorithm from `_split_long_text()` in `src/synthesis/synthesizer.py` — copy it here so the synthesizer can import from chunker.
   - Same NLTK sent_tokenize, same 280-char default.

3. `chunk_segments_by_speaker(segments: list[dict], engine_type: str = "qwen3") -> list[dict]`:
   - Input: list of attributed segment dicts (from attributed.json). Each has `text`, `speaker`, `chapter`, `type`, `id`.
   - Per user decision: split by speaker — separate chunks when speaker changes, even within a paragraph.
   - Algorithm:
     a. Iterate segments in order.
     b. For each segment, select chunker based on `engine_type` ("qwen3" -> `chunk_text_qwen`, "chatterbox" -> `chunk_text_chatterbox`).
     c. Split segment text using selected chunker.
     d. For each chunk, create a new segment dict preserving all original fields (`speaker`, `chapter`, `type`, etc.) but with the chunk text and a new sub-ID: `{original_id}.{chunk_index}` (e.g., "42.0", "42.1").
     e. Speaker boundaries are already naturally handled because each input segment has a single speaker — the chunker just splits long single-speaker segments.
   - Return the expanded list of segment dicts.

Include `_ensure_nltk_data()` call (import from `src/parser/segmenter.py` or inline the pattern — check punkt_tab then punkt). Follow established codebase pattern from Phase 1.

  <action>
1. Update `src/matching/clip_selector.py`:
   - Modify `select_reference_clip()` to target 10-15 second clips instead of just "longest".
   - Current logic picks largest WAV by file size. New logic:
     a. Scan all WAVs for the speaker (existing glob logic).
     b. Compute duration from file size: `duration_s = file_size / (24000 * 2)` (24kHz, 16-bit mono — LibriTTS-R standard format).
     c. Score each clip: prefer clips closest to 12.5s (midpoint of 10-15s range). Score = `1.0 / (1.0 + abs(duration_s - 12.5))`.
     d. Filter: exclude clips shorter than 5s (existing minimum) or longer than 25s (avoid generation hangs per research).
     e. Return the highest-scoring clip path.
     f. If no clips in 10-15s range exist, fall back to the longest clip under 25s (with a log warning).
   - Keep `_MIN_CLIP_BYTES = 120_000` for backward compatibility.
   - Add a new function `select_reference_clip_with_transcript(speaker_id, libritts_root) -> tuple[str | None, str | None]`:
     a. Call `select_reference_clip()` to get clip path.
     b. If clip found, look for the corresponding `.normalized.txt` file. LibriTTS-R naming: `{speaker}_{chapter}_{utt_start}_{utt_end}.wav` has a matching `{speaker}_{chapter}_{utt_start}_{utt_end}.normalized.txt` in the same directory.
     c. Return `(clip_relative_path, transcript_text)` or `(clip_relative_path, None)` if transcript not found.

2. Create `src/synthesis/voice_prep.py`:
   - `prepare_voice_reference(speaker_id: str, clip_path: str, libritts_root: Path) -> VoiceReference`:
     - `VoiceReference` is a simple dataclass: `clip_path: str`, `transcript: str | None`, `duration_s: float`, `snr_score: float | None`.
     - Compute basic SNR score using RMS-based method (no external dependency needed):
       a. Read WAV with `soundfile.read()` → numpy array.
       b. Split into voiced/unvoiced frames (simple energy threshold: frames with RMS below 1% of max RMS are "noise").
       c. SNR = `20 * log10(rms_signal / rms_noise)` dB.
       d. Log the SNR score. If SNR < 15 dB, log a warning (clip may be too noisy).
       e. If SNR computation fails (empty audio, all silence), set `snr_score = None` and log warning. Per user decision (Claude's discretion on SNR filter failure): use clip with warning, don't skip.
     - Look up transcript: use `select_reference_clip_with_transcript` or read the `.normalized.txt` companion file.
     - Compute actual duration from audio array length / sample_rate.
     - Return populated `VoiceReference`.
   - `prepare_all_voice_references(voice_map: VoiceMap, libritts_root: Path) -> dict[str, VoiceReference]`:
     - Iterate voice_map.narrator + voice_map.characters.
     - Call `prepare_voice_reference()` for each.
     - Return dict keyed by character_name.
     - Log summary: N references prepared, M with transcripts, K with SNR warnings.
  </action>
